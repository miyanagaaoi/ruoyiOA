# Proposal — OA 2.0 B4：采购 / 销售 / 库存与出入库（参考仓库移植）

> **覆盖需求**：`REQ-PUR-001`、`REQ-SAL-001`、`REQ-STK-001..006`、`REQ-NFR-007`（精度）、`REQ-NFR-008`（并发）、`REQ-DATA-002`（库存域部分）
> **验收覆盖**：`AC-72..AC-76`、`AC-78`、`AC-82`
> **依赖**：`oa-v2-overview`（`platform/module-boundary`、`platform/delivery-gate`）；`oa-contract-ledger`（往来单位档案与合同台账——单据的"关联合同"与供应商/客户引用依赖它，未交付则只能文本兜底，属降级交付）；`oa-print-builtin-templates`（单据打印复用其"按单据类型选内置模板"机制）
> **批次**：B4，随 2.2 交付

## Why

OA 2.0 的第二批（B4）要把参考仓库 `miyanagaaoi/contract`（CTMS，Python FastAPI + Vue3）的**进销存**能力移植进 RuoYi-OA（Java 8 + Vue2）：8 类业务单据（采购申请/采购单/销售申请/销售订单/入库单/出库单/盘点单/调拨单）、下推链路、库存结存与流水、调拨与盘点，约 39 张表中的库存域部分与 ~120 个端点（`doc/2.0/参考仓库-CTMS-移植清单.md` §2~§4）。

为什么必须**照口径移植**而不是"顺手优化"：参考仓库已被 UAT 冻结了一批**与直觉相反、写错不会报错但数据会错**的口径 —— 金额"先舍入再汇总"（否则导出/打印/对账出现 1 分钱差异）、「货品总额度」按 `biz_type` 判入库方向而非按 `qty_change > 0`（否则红冲无法冲减）、库存类单据 `approved` 即终态（不使用 `completed`）、盘亏豁免负库存校验、调拨两阶段先校验后写入且不计入额度。

同时**必须补齐参考仓库的已知缺陷**：它靠 SQLite 串行写掩盖了过账竞态（无行锁、结存行"先查后插"无并发保护），MySQL 下并发审核会丢更新并污染库存。本变更集把 `SELECT ... FOR UPDATE` 行锁、显式事务、结存唯一索引 + 重复键重试写成硬要求。

## What Changes

- **新增库存主数据能力**：物料、物料类型（树、仅叶子可挂物料）、计量单位（小数位 0~4）、仓库；档案只启停用不物理删除，被引用时禁止删除。
- **新增采购线能力**：采购申请单 → 采购单 → 入库单的完整状态机与下推链路，`ordered_qty`/`received_qty` 剩余量校验与回写、归零即完成、上游有未作废下游时禁止反审核。
- **新增销售线能力**：销售申请单 → 销售订单 → 出库单，与采购线对称，`shipped_qty` 语义。
- **新增库存作业能力**：入库单/出库单（**审核即过账、反审核红冲**）、调拨单（两阶段、一单两条流水、不计额度）、盘点单（全盘/抽盘、审核按差异自动生成盘盈入库/盘亏出库单并过账、**盘亏豁免负库存校验**、反审核级联处理生成单）。
- **新增库存账能力**：库存明细（按「商品类型-物料名称」展示、「货品总额度」列）与库存流水（**只增不改**，红冲以负数追加、原流水保留），结存一致性不变式 `结存数量 == SUM(流水数量变动)` 与运维校验/修复接口。
- **新增精度与并发硬要求**：全部金额/数量用定点小数（`BigDecimal`），金额 scale=2、单价 scale=4、数量按单位小数位 scale=3，**先舍入再汇总**；过账/红冲走显式事务 + 行锁，结存行唯一索引 + 重复键重试。
- **明确不复用/不移植**：不移植参考仓库的账号、组织树、自研令牌、代码常量权限表、KV 字典、打印模板表、SQLite 备份；不移植 `CTMS_AUTH_ENABLED=0` 类免认证后门（见下"依赖"）。
- 本变更集**只做规划**，不改任何源代码。

## Capabilities

### New Capabilities

- `erp/procurement`: 采购申请单与采购单 —— 单据状态机（草稿/待审核/已审核/已完成/已作废）、行项与金额口径、「申请 → 采购单 → 入库」下推与剩余量回写、归零即完成、下游守卫。
- `erp/sales`: 销售申请单与销售订单 —— 与采购线对称的状态机、行项与金额口径、「申请 → 订单 → 出库」下推与剩余量回写（`shipped_qty`）。
- `erp/inventory-operations`: 入库单、出库单、调拨单、盘点单 —— 审核即过账、反审核红冲（负数追加、原流水保留）、负库存校验与默认拒绝、调拨两阶段双向写入、盘点差异自动生成盘盈/盘亏单并过账（盘亏豁免负库存校验）、盘点反审核级联。
- `erp/stock-ledger`: 库存明细与库存流水 —— 结存按（物料 × 仓库）唯一、流水只增不改、变动后结存快照、货品总额度口径、结存一致性不变式与运维校验/修复接口、并发过账不丢更新。
- `erp/stock-master-data`: 物料、物料类型、计量单位、仓库 —— 编码唯一与自动生成、类型树层级与叶子约束、单位小数位范围、删除与停用的引用守卫、单据快照不受主数据改名影响。

### Modified Capabilities

无。本变更集不声明任何 `MODIFIED` 能力（`openspec/specs/` 当前为空，且总纲尚未归档）。

> **依赖声明（不在本变更集内实现，也不在此改写）**：
> 本变更集依赖 `oa-v2-overview` 的 `platform/module-boundary`（复用 OA 认证/组织/权限/字典/编号/附件/日志/打印，禁止第二套体系）与
> `platform/delivery-gate`（既有回归资产全绿、V1 验收不回归、新增能力同批交付回归脚本、移植缺陷不得一并搬入）；
> 并依赖 `oa-contract-ledger` 的 `ctms/business-partners` 与 `ctms/contract-ledger`（单据可关联合同、往来单位已档案化）。
> 若总纲尚未归档，本变更集不引用 `MODIFIED`，以自身新能力承载要求，待总纲归档后再收敛。

## Impact

- **规格**：新增 5 个能力规格，路径为 `openspec/changes/oa-purchase-sales-stock/specs/erp/{procurement,sales,inventory-operations,stock-ledger,stock-master-data}/spec.md`。
- **后端**：新建 `ruoyi-*` 业务模块（建议独立域模块，如 `ruoyi-erp`，或按 OA 惯例拆分），含 8 类单据的表头/行项、库存结存与流水、4 类主数据的 Controller/Service/Mapper；根 `pom.xml` 的 `<modules>` 与 `ruoyi-admin/pom.xml` 需登记；复用 `ruoyi-serial`（单据/档案编号）、`ruoyi-file`（附件挂业务对象）、`@Log`（操作日志）、`ruoyi-workflow/print`（打印）、`sys_dict_*`/`sys_config`（字典与系统参数，含"是否允许负库存"）。
- **数据库**：新增增量 DDL 脚本（含结存表 `(物料, 仓库)` 唯一索引、流水表 `(物料, 仓库, id)` 与 `(单据类型, 单据 id)` 索引、外键与非空约束），并同步补齐 `sql/table.sql`/`sql/data.sql` 基线；菜单与权限点走独立增量 `二开-*.sql`。
- **前端**：新增主数据页（物料/物料类型/计量单位/仓库）与 8 类单据的列表页/表单页，复用"配置驱动的单据列表壳 + 单据表单壳 + 行项表 + 下推对话框"结构，避免 8 份拷贝；Element Plus → Element UI 的语法改写（日期格式串 `YYYY-MM-DD` → `yyyy-MM-dd` 等）。
- **权限**：新增 `pur:*` / `sal:*` / `stk:*` 域权限点（全小写、冒号分隔、动作集含 `approve`/`unapprove`/`void`/`push`/`export`），并登记进 `sys_menu` 与角色授权；单据/结存/流水的数据范围按"创建人 + 归属部门"口径显式映射。
- **依赖**：不新增第三方依赖；不移植参考仓库的认证、组织、权限常量、KV 字典、打印模板表、SQLite 备份与免认证后门。
- **验收映射**：`REQ-PUR-001`、`REQ-SAL-001`、`REQ-STK-001`~`REQ-STK-006`、`REQ-NFR-007`（精度）、`REQ-NFR-008`（并发）；`AC-72`~`AC-76`、`AC-78`。
- **风险**：过账/红冲/下推回写的事务一致性（数据正确性）、数据范围口径差异（权限）、"先舍入再汇总"（精度）为最高风险三处；前端 8 类单据页为重写规模风险。
