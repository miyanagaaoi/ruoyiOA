# Spec Delta

## Purpose

定义交付门禁中的**浏览器端到端回归能力**：以真实浏览器驱动目标前端，验证「接口正确但页面错误」这一类无法被接口脚本与纯 Node 用例覆盖的回归，且不修改任何共享运行配置与业务代码。

## ADDED Requirements

### Requirement: 真实浏览器驱动的端到端验证

交付门禁 SHALL 包含一个由真实浏览器驱动目标前端的端到端套件，覆盖登录链路与至少一条业务链路；该套件 SHALL 纳入 DEV-ENV 的固定门禁清单。

#### Scenario: 套件纳入门禁并全绿
- **WHEN** 交付前按 `DEV-ENV.md` 的固定门禁清单执行浏览器端到端套件
- **THEN** 全部用例通过，退出码为 0，该次交付方可被标记为完成

#### Scenario: 页面级回归被拦截
- **WHEN** 前端某业务页出现「后端接口返回 200，但页面渲染/交互错误」的回归
- **THEN** 浏览器端到端套件以非 0 退出码结束，该次交付被阻断

### Requirement: 登录一次性获取并在用例间复用

套件 SHALL 通过真实登录页完成认证一次，并把该登录态复用于其余用例；认证 MUST NOT 依赖人工输入，MUST NOT 依赖图像识别。

#### Scenario: 登录态跨用例复用
- **WHEN** 认证用例完成一次登录后，其余用例开始执行
- **THEN** 其余用例直接进入业务页，不再重复执行登录交互

#### Scenario: 验证码无需人工参与
- **WHEN** 目标系统开启了图形验证码
- **THEN** 套件在无人值守下完成登录，不出现等待人工输入的挂起

### Requirement: 认证过程不修改共享运行配置

套件获取验证码 MUST NOT 关闭或改写系统的验证码开关，也 MUST NOT 修改数据库或缓存中的任何系统配置。

#### Scenario: 验证码开关保持开启
- **WHEN** 浏览器端到端套件执行前后分别读取验证码开关配置
- **THEN** 两次读取的值均为开启，真实用户在套件运行期间仍能看到验证码输入框

#### Scenario: 套件异常退出不留下配置变更
- **WHEN** 套件在认证阶段失败或以非 0 退出码终止
- **THEN** 系统的验证码开关等共享配置保持与执行前一致

### Requirement: 环境噪声与业务失败的区分口径

套件 SHALL 把已知的环境级噪声排除在失败判定之外，同时 MUST 继续把业务层面的异常判为失败。环境级噪声 SHALL 以单一的集中口径定义，MUST NOT 由各用例各自声明。

#### Scenario: 未启动的可选依赖不导致失败
- **WHEN** 目标环境中可选依赖（如即时通讯服务）未启动，页面因此产生连接失败的浏览器控制台记录
- **THEN** 该记录不使用例失败，套件仍可全绿

#### Scenario: 业务异常仍然失败
- **WHEN** 某个被覆盖的业务接口返回 4xx/5xx，或页面出现渲染错误
- **THEN** 对应用例失败，套件以非 0 退出码结束

### Requirement: 失败可诊断

用例失败时，套件 SHALL 留存可定位问题的现场产物（页面截图、操作轨迹、录屏中至少两种），并 MUST 以非 0 退出码结束。

#### Scenario: 失败留下可复现现场
- **WHEN** 某条用例断言失败
- **THEN** 该次运行的报告目录中存在该用例的截图与操作轨迹，可直接用于定位

#### Scenario: 退出码反映结果
- **WHEN** 全部用例通过 / 存在失败用例
- **THEN** 套件分别以 0 / 非 0 退出码结束

### Requirement: 套件依赖与前端应用产物隔离

套件 SHALL 使用独立于前端应用构建产物的依赖集合，MUST NOT 修改前端应用已入库的依赖清单与依赖锁文件。

#### Scenario: 应用依赖清单与锁文件不变
- **WHEN** 浏览器端到端套件已落地并可运行
- **THEN** 前端应用的依赖清单与依赖锁文件与该套件引入前逐字一致

#### Scenario: 应用构建不受影响
- **WHEN** 在引入套件后执行前端应用的既有构建与既有纯 Node 用例
- **THEN** 二者行为与引入前一致

### Requirement: 复用环境已有浏览器

套件 MUST NOT 在执行时下载浏览器内核，SHALL 复用运行环境中已安装的浏览器；在没有外网的环境下 SHALL 仍可执行。

#### Scenario: 断网可执行
- **WHEN** 运行环境无法访问外网，但已安装浏览器且套件依赖已就位
- **THEN** 套件正常执行并给出结果

#### Scenario: 不产生内核下载
- **WHEN** 安装套件依赖并首次执行
- **THEN** 不发生浏览器内核的下载动作

### Requirement: 可重复执行与既有门禁资产互斥

套件 SHALL 可重复执行且结果一致。会写入数据的用例 SHALL 使用可识别的测试数据前缀并在收尾清理，MUST NOT 在既有接口脚本持锁期间改写同一批数据。

#### Scenario: 连续两次执行结果一致
- **WHEN** 在环境不变的前提下连续执行两次套件
- **THEN** 两次结果一致，且第二次执行不产生新的残留数据

#### Scenario: 不与接口脚本并发改写
- **WHEN** 某个既有接口脚本已持有运行锁
- **THEN** 浏览器端到端套件不与其并发执行会写数据的用例

### Requirement: 不依赖库中既有业务数据

用例 SHALL 在目标实体无任何数据时同样通过（断言空态），或自造带前缀的夹具后清理；MUST NOT 以「库中恰好存在数据」作为通过前提。

#### Scenario: 目标实体为空时通过
- **WHEN** 被覆盖的业务实体在库中不存在任何记录
- **THEN** 用例以空态断言通过，不因「表里没数据」而失败

### Requirement: 环境未就绪时可识别地失败

当前置环境未就绪（前端或后端未监听）时，套件 SHALL 以明确的失败信息终止，该次交付 MUST NOT 被记为通过。

#### Scenario: 前置未起时的行为
- **WHEN** 前端页面或后端接口未就绪就执行套件
- **THEN** 套件以非 0 退出码结束并指出未就绪的目标，不出现长时间静默挂起
