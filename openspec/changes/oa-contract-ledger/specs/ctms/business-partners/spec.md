# Spec Delta

## Purpose

承载客户与供应商档案的登记、启停用与删除管控，以及合同甲乙方向档案引用的收敛与文本兜底，是往来单位在合同侧被引用的唯一真源。

## ADDED Requirements

### Requirement: 客户档案登记与唯一性

系统 SHALL 支持客户档案的登记与编辑，字段 SHALL 包含客户编码、客户名称、简称、税号、联系人、联系电话、地址、开户银行、银行账号、授信额度、等级与状态。客户编码与客户名称 MUST 在库内唯一；客户简称 MUST 为选填。系统 MUST 拒绝重复的客户编码或客户名称并给出明确提示。

#### Scenario: 重复编码被拒绝
- **WHEN** 用户新增客户时填写的编码与既有客户相同
- **THEN** 系统拒绝保存并提示编码已存在

#### Scenario: 重复名称被拒绝
- **WHEN** 用户新增客户时填写的名称与既有客户相同
- **THEN** 系统拒绝保存并提示客户名称已存在

#### Scenario: 简称可为空
- **WHEN** 用户新增客户时只填写编码与名称、不填简称
- **THEN** 系统保存成功

### Requirement: 供应商档案登记与必填口径

系统 SHALL 支持供应商档案的登记与编辑，字段在客户档案基础上增加供货范围与账期天数。供应商简称 MUST 为必填（与客户不同）；新增或修改时提交空的简称 MUST 被拒绝。账期天数 MUST 为不小于 0 的整数，负数 MUST 被拒绝。

#### Scenario: 供应商简称为必填
- **WHEN** 用户新增供应商但未填写简称
- **THEN** 系统拒绝保存并提示简称必填

#### Scenario: 账期天数负数被拒绝
- **WHEN** 用户把供应商账期天数填为 -1
- **THEN** 系统拒绝保存

#### Scenario: 账期天数为 0 可保存
- **WHEN** 用户把供应商账期天数填为 0，其它必填齐全
- **THEN** 系统保存成功

### Requirement: 往来单位启停用与引用保护

往来单位档案 MUST 只做启停用，MUST NOT 提供物理删除能力；停用后 MUST 从「新增合同可选的档案列表」中排除，但已引用该档案的历史合同 MUST 仍能正常展示其档案名称。删除接口 MUST 仅在该档案没有任何引用时放行，否则 MUST 拒绝并提示存在引用。

#### Scenario: 停用后不可新选
- **WHEN** 某客户被停用，用户新增销售合同并打开客户选择器
- **THEN** 该客户不出现在可选列表中

#### Scenario: 停用后历史合同仍可展示
- **WHEN** 一份历史销售合同引用了已被停用的客户
- **THEN** 合同列表与详情仍展示该客户的名称与编码，不报错

#### Scenario: 有引用时禁止删除
- **WHEN** 用户尝试删除一个已被 3 份合同引用的供应商档案
- **THEN** 系统拒绝并提示存在引用

### Requirement: 合同甲乙方档案化引用与文本兜底

合同的甲乙方 SHALL 支持引用往来单位档案：采购类合同引用供应商作为乙方、销售类合同引用客户作为甲方。当提交了档案标识时，系统 MUST 校验档案存在，不存在 MUST 拒绝并提示档案不存在。当未显式提供对应的甲乙方文本时，系统 MUST 以档案名称回填文本快照。未绑定档案的合同 MUST 仍以文本展示甲乙方，MUST NOT 阻塞列表、详情或导出。

#### Scenario: 档案不存在被拒绝
- **WHEN** 用户提交销售合同时传入一个不存在的客户档案标识
- **THEN** 系统拒绝并提示「客户档案不存在」

#### Scenario: 文本快照自动回填
- **WHEN** 用户新增采购合同并选择供应商「某某阀门有限公司」但未填写乙方文本
- **THEN** 合同乙方文本被自动写为「某某阀门有限公司」，并保留该供应商档案标识

#### Scenario: 未绑定档案的合同正常展示
- **WHEN** 一份历史合同既无客户也无供应商档案标识，仅乙方文本为「老客户甲」
- **THEN** 列表与详情正常返回并展示文本「老客户甲」，不报错

#### Scenario: 档案方向按合同类型映射
- **WHEN** 用户新增采购类合同并选择了一份供应商档案
- **THEN** 该档案被写入合同的供应商引用，而非客户引用

### Requirement: 往来单位档案不做数据范围隔离

往来单位档案 SHALL NOT 参与合同台账的数据范围隔离：具备查询权限的用户 MUST 能看到全部未停用的客户与供应商档案，MUST NOT 因为档案创建人不同或部门不同而被隐藏。合同侧的数据范围 MUST 只在合同实体上生效。

#### Scenario: 他人创建的档案可见
- **WHEN** 用户 A（仅本人范围）打开客户选择器，档案由用户 B 创建
- **THEN** 该客户档案出现在可选列表中

#### Scenario: 档案隔离不影响合同隔离
- **WHEN** 用户 A 仅本人范围，查看一份由用户 B 创建、引用了同一客户档案的合同
- **THEN** 该合同不可见（合同隔离生效），但客户档案本身在档案页可见
