# 错误态铺开：把「永久转圈」这类静默故障清干净

> **日期**：2026-10-04（第三轮）
> **仓库**：`ruoyi-vue-oa-ui-master`（前端）
> **起因**：第二轮把错误态铺到自研模块，但把「其余上游页面」留成了 TODO。本轮做完。

---

## 1. 先说结论：真实缺陷不是"静默 catch"，是"取数失败后状态不复位"

第二轮我给的 TODO 描述是「全仓还剩 ~60 处静默 `.catch(() => {})`」，并打算"只改主数据加载"。
**实际动手前做了精确分类，发现这个描述是错的**，照它做会白干：

| 初判 | 精确分类后的真相 |
| --- | --- |
| 69 处空 `.catch(() => {})` | 其中绝大多数是 `this.$modal.confirm(...).then(请求).catch(() => {})` —— 一个 catch 同时接"用户取消"和"请求失败"（见 §3 类 3） |
| 「静默」= 用户看不到失败 | **不成立**：`src/utils/request.js` 的拦截器对 401/500/601/其它非 200/网络错误**都会弹提示**。所以"用户完全不知道失败了"这个说法是错的 |

真正会让用户卡住的，是另一件事：**取数失败后 `loading` 永远停在 `true`** —— 表格永久转圈，还残留上一次的数据，用户会以为"库里没数据"。

## 4. 修法规范

### 4.1 样板

`src/views/system/dict/index.vue` 是本轮的样板。四处改动：

```js
// 1) import
import DataLoadError from "@/components/DataLoadError";
import { describeError } from "@/utils/errorMessage";

// 2) 注册
components: { DataLoadError },

// 3) data
loadError: "",
loadErrorCause: "",

// 4) 取数：开头清错误 + catch 里三件事缺一不可
getList() {
  this.loading = true;
  this.loadError = "";          // 重试成功后横幅自动消失
  this.loadErrorCause = "";
  listType(...).then((response) => {
    this.typeList = response.rows;
    this.total = response.total;
    this.loading = false;
  }).catch((err) => {
    this.loading = false;       // ① 复位，否则永久转圈
    this.typeList = [];         // ② 清数据，否则"旧数据 + 错误提示"并存
    this.total = 0;
    const d = describeError(err);
    this.loadError = d.text;    // ③ 可见错误态
    this.loadErrorCause = d.cause;
  });
}
```

模板（`v-if`/`v-else` **必须紧邻**）：

```html
<DataLoadError v-if="loadError" :text="loadError" :cause="loadErrorCause" @retry="getList" />
<el-table v-else v-loading="loading" :data="typeList" ...>
```

### 4.2 为什么单独做 `DataLoadError` 而不是复用 `StateBlock`

`StateBlock` 是"整块区域状态"，会顶掉 `el-table`；而 RuoYi 列表页模板高度同构，
插一条横条 + 给表格挂 `v-else` 是**改动最小、最不容易碰坏布局**的做法。横条行高固定，不引起像素跳动。

### 4.3 三类必须遵守的细节

1. **数据变量名不要假设是 `list`** —— 本轮实际出现的名字有 `typeList` / `userList` / `roleList` /
   `deptList` / `menuList` / `configList` / `postList` / `dataList` / `jobList` / `jobLogList` /
   `asyncList` / `logList` / `entrustList` / `secretaryList` / `tableList` / `noticeList` /
   `informationList` / `recycleList` / `definitionList` / `expressionList` / `listenerList` /
   `sealList` / `templateList` / `formList` / `doneList` / `groupList` / `cacheNames` …。
   **以 `.then` 里实际赋值的那个为准**；`total` 原代码没有就不要凭空加。
2. **只有当该方法是"该页面主表格的取数方法"、且模板里能明确找到对应 `<el-table>` 时**才插横幅；
   组件、弹窗、侧栏树、下拉选项一律"只改 JS"（复位 + 清数据 + `$modal.msgError`）。
3. **`v-if` 与 `v-else` 不能共存**：`system/dept`、`system/menu` 的表格原本是 `v-if="refreshTable"`
   （用于强制重建树表），已改为唯一等价写法 `v-else-if="refreshTable"`。

## 8. 第二轮：把判据升级成「每个 loading 标志都必须有配对复位」

§7 承诺的"更强的判据"就是这一节。**结论：靠正则做不到，必须上 AST。**

### 8.1 为什么手写解析器不行（踩了两次）

第一版我写了个手搓的括号栈解析器，**78 条命中里绝大多数是误报**，连我刚修好的 `system/dict/index.vue` 都被报成缺陷。原因：

RuoYi 的链式写法是

```js
listXxx(...).then((response) => {
  ...
}).catch((err) => {
```

`}).catch((err) => {` 这一行**净开括号数为 0**（一闭一开），所以 `.catch` 这一帧根本没入栈，
catch 里的复位被算成了 then 的。**判据一旦错，扫出来的清单就是垃圾。**

改用 `@babel/parser` + `@babel/traverse`（项目 `node_modules` 里就有）后，又踩了两个坑，都记下来：

1. **边界不能取 `getFunctionParent()`** —— 它返回**最近的**函数，而 `.then`/`.catch` 的回调本身就是函数，
   于是循环一进去就停了，永远走不到 `CallExpression`，所有复位还是被判成"函数体"。
   正确做法是**显式以被分析的方法为边界**向上走。
2. **`walkUp` 要返回值而不是返回路径** —— 我的谓词返回的是上下文字符串（`'thenCb'` / `'catchCb'` / `'finally'`），
   但 `walkUp` 返回的是匹配到的**路径**，于是上下文被打成了节点源码。要单独写一个"返回谓词值"的变体。

### 8.2 判据

对方法体内每个 `this.<flag> = true`（flag 匹配 `/loading/i`，**不再限定叫 `loading`**）：

- **`failOk`** = 存在复位位于 `finally`，或位于 `catch` 子句/`.catch` 回调且其内无 `if`/循环包裹；
- **`successOk`** = 存在复位位于 `finally`、`.then` 回调、`try` 块或函数体，且其内无 `if`/循环包裹；
  但 **async 函数里出现在 `await` 之后的普通复位不算数**（`await` 抛错就到不了那里）；
- 补充：`if (A) { 复位 } else { 复位 }` 两侧都有 → 视为无条件；
- **必须排除"同时包住置位与复位"的条件块**：形如
  `if (userId) { this.loading = true; getX().then(...).catch(...) }`，
  这个 `if` 与"复位有没有保证"无关；不排除就会把正确代码误报成缺陷（`system/user/authRole.vue` 就吃过这个亏）。

### 8.4 另一类缺陷：`.catch((this.X = 布尔值))` 笔误（**全仓 6 处 / 4 个文件**）

```js
.catch((this.loading = false));   // 括号套了两层
```

传进去的是**赋值表达式的值**（`false`），而 `false` 不是函数 —— Promise 会**静默忽略**这个回调；
同时那个赋值会**同步立即执行**（请求还没回来就把标志清了）。两种后果：

- `.catch((this.loading = false))`：加载提示根本不显示（被立刻清掉），失败被静默忽略 —— 4 处；
- `group-table.vue` 的 `.catch((this.loading = true))`：失败时标志停在 `true` → **永久转圈** —— 1 处。

这类笔误**只有 AST 能可靠发现**（正则要额外处理嵌套括号与换行）。已全部改为真函数 + `.finally` 复位，全仓复扫 0 命中。

### 8.5 修法：统一用 `.finally()`

对"复位"这件事，`.finally(() => { this.xxxLoading = false; })` 是最省事也最不容易出错的写法：
它天然覆盖成功与失败两条路径，且不依赖业务分支。本轮 12 处全部这样改（`submitForm` 那种 async 的用 `try/catch/finally`）。
