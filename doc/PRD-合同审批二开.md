## 第1章 项目背景与目标

### 1.1 背景

**业务侧**

- 集团为**集团—公司—部门—科室**四级组织的多法人结构，合同类文件现行流转是"纸质《集团合同类文件流转审批单》+ 手写签批 + 人工传递 + 用印"。
- 现行纸质流程的痛点：
  1. **传递慢**：提报单位 → 责任部门 → 会审部门（经营/经济/人力/行政/法务）→ 集团分管领导 → 集团董事长 → 公文回传 → 印鉴证照管理部门，全部靠人跑；
  2. **不可追溯**：签批意见手写在纸上，事后无法统计"谁在什么时候批了什么"，也无法量化审批耗时；
  3. **审批与用印脱节**：纸质单批完再去盖章，盖章与合同正本、扫描件之间没有系统级绑定；
  4. **版式不统一**：各单位自行打印，栏目缺失、扫描件编号不连贯。

**工程侧（RuoYi-Vue-OA 现有能力）**

| 能力 | 现状 | 证据 |
| --- | --- | --- |
| 流程引擎 | Flowable 封装（定义、实例、任务、历史、评论） | `ruoyi-flowable/**` |
| 流程设计器 | **全功能 BPMN 建模器**（bpmn-js + 属性面板 + 监听器/多实例/表达式） | `ruoyi-vue-oa-ui-master/src/components/Process/**` |
| 流程部署 | 保存 BPMN XML 即部署 | `FlowDefinitionController.java:105` `POST /flowable/definition/save` |
| 动态表单 | form-generator 风格设计器 + 解析渲染 | `src/views/tool/build/**`、`src/components/parser/Parser.vue` |
| 表单数据 | 整单 JSON 落一列 | `t_workflow_form.form_data`（`sql/table.sql:2366`） |
| 模板配置 | 模板绑定流程定义 + 表单 + 正文/附件/消息开关 | `t_template`（`sql/table.sql:2146`） |
| 待办/已办/我起草/回收站 | 已有 | `ruoyi-todo/**`、`ruoyi-workflow/**` |
| 正文与盖章 | 印章由系统**生成**（公章/合同章/发票章），可预览/启用；正文可盖章、可还原 | `WorkflowMainSealController.java:93,104`、`t_workflow_main_seal`（`sql/table.sql:2379`） |
| PDF 签章库 | 关键字定位盖章、骑缝章、手写签名、水印、加密 | `ruoyi-seal/**`（`PdfService.java:99`、`PdfUtil.java:200`） |
| 流水号 | 合同编号 `HT` 已内置，规则=固定值/日期/流水号 | `BusinessTypeEnum.java:8`、`CodeConfigRule.java:30` |
| 委托/秘书 | 已有 | `ruoyi-worksetting/**` |
| **打印** | **无**（仅附件区有一处被注释的打印按钮） | `flow-attachment.vue:72` |
| **手写签名** | **审批环节无**（PDF 库有底层能力，未接入审批动作） | 见第 5 章 |

**结论**：引擎、表单、盖章、流水号是**存量资产**，可直接复用；缺的是"**面向业务用户的流程配置入口**""**打印**""**节点级签名**"这三块。

### 1.2 项目目标

- **G1 流程设计简化**：把"画 BPMN 图"降级为"配节点清单"。业务管理员（集团/子公司流程管理员）**不接触 BPMN、不写表达式**即可完成一条合同审批流程的配置与发布；底层仍由 Flowable 执行，已发布流程与在途单据不受影响。
- **G2 表单打印**：一键生成与纸质《集团合同类文件流转审批单》**版式一致**的 A4 打印件（含表单数据、各节点签批栏、附件清单、条码/二维码），支持打印预览、浏览器打印、另存 PDF。
- **G3 签名组件选配**：按**节点**选配签名方式（手写签名 / 预存签名 / 电子印章 / 免签），签名与审批动作强绑定并留痕，签名图片落到打印件的对应签批栏。

### 1.3 成功指标

| 指标 | 目标值 | 口径 |
| --- | --- | --- |
| 单条合同审批流程配置耗时 | ≤10 分钟 | 从"新建流程"到"发布可用"，熟悉业务的管理员 |
| 流程设计器完成一条 5 节点流程的操作步数 | ≤6 步 | 节点链 + 每节点一次配置弹窗 |
| 设计器必填项错误率 | ≤5% | 发布校验拦截并给出定位提示 |
| 打印件与纸质流转单栏目一致性 | 关键栏目 100% 对齐 | 见 7.8 字段映射表 |
| 打印件页数 | 常规 1 页；超长自动分页并标注"第 X 页 / 共 Y 页" | A4 纵向 |
| 需签名节点的签名采集率 | 100% | 未签名不得提交（节点策略为"必需"时） |
| 签名/盖章记录可追溯 | 100% | 记录含 人、时间、节点、任务、IP、文件哈希 |
| 业务管理员独立配置率 | ≥90% | 无需开发介入 |

### 1.4 与既有资料的关系

- **`集团合同审批流转单.png`**：纸质版式基准。第 4.1 节逐行解析，第 7.8 节给出"纸质栏目 ↔ 系统字段"映射，是打印模板的验收依据。
- **`合同审批表单填写页面.jpg`**：电子填写页基准（飞书合同审批填写页）。用于确定**表单分组**（申请详情 / 我方信息 / 对方信息）与字段必填口径。
- **`feishu-approval-designer-reference.md`**：流程设计器与表单设计器的**功能对标池**。本 PRD 采用其"有序节点链 + 节点配置 + 兜底分支"的交互范式（参考其 §4.1/§4.2/§4.3），但**不**照搬其数据模型。
- **`集团OA审批系统 PRD`（另一仓库）**：业务口径来源（7 节点主干、四类单据、签名、A4 打印、审计留痕）。本文件在**同一业务口径**下给出 **RuoYi-Vue-OA + Flowable 技术栈**的落地口径；两者冲突时，以本文件为准。

## 第3章 术语与角色

### 3.1 术语

| 术语 | 说明 |
| --- | --- |
| 模板（Template） | 业务上的一张"审批单类型"，绑定 1 个流程定义 + 1 张表单 + 正文/附件开关。对应 `t_template` |
| 流程定义（Definition） | Flowable 中的流程模型，由设计器发布产生；存储为 BPMN XML |
| 流程实例（Instance） | 一次实际的合同审批单流转 |
| 任务（Task） | 节点上待某人处理的待办 |
| 节点（Node） | 设计器中的一个环节，类型为 发起/审批/办理/抄送/**条件分支**（本期）或 并行分支（P1） |
| 动态表单 | 由表单设计器产出的 JSON 描述 + 运行时渲染的表单，数据整单 JSON 落库 |
| 分组标题 | 表单中的分节标题（如"我方信息"），不可填写，仅排版 |
| 正文 | 合同正文文件（Word/PDF），可"上传"或"书签替换"生成，可盖章 |
| 附件 | 随单上传的扫描件、资质文件等 |
| 签批栏 | 打印件上留给各节点签名的表格区域（对应纸质单的"公文接收及处理""集团领导意见"） |
| 签名 | 审批人在自己的签批栏上留下的**手写签名图片**或**预存签名图片** |
| 盖章 | 法定代表人章外，盖在**正文文件**上的电子印章（公章/合同章/发票章） |
| 预存签名 | 用户在个人中心维护的默认签名图片，审批时可一键调用 |
| 免签 | 该节点不需要签名即可提交 |
| 兜底分支 | 条件分支中的"其他情况"，不可删除，防止单据卡死 |

### 3.2 角色

| 角色 | 职责 | 系统权限 |
| --- | --- | --- |
| 发起人 | 填写并提交合同审批单，上传附件/正文 | 本人单据的创建、查看、撤回、打印 |
| 审批人 | 在待办中处理单据：查看表单、填意见、签名、同意/退回/驳回 | 被指派任务的可见与操作 |
| 办理人 | 用印、归档等业务办理动作（不打审批结论） | 办理节点的操作 |
| 抄送人 | 只读知会 | 只读 + 打印 |
| 流程管理员 | 配置模板与流程（简化设计器）、维护签名策略 | 设计器与模板配置 |
| 系统管理员 | 用户/角色/组织/字典/流水号/印章库 | 全量后台 |
| 打印人 | 任何有权查看该单据的人（打印为"查看权"的延伸） | 打印 + 打印日志留痕 |

### 4.2 电子填写页（合同审批（含用印））字段与分组

参考 `合同审批表单填写页面.jpg`：

```

  合同名称 *            单行文本
  合同类型 *            下拉单选

## 第6章 需求一：简化版流程设计器

### 6.1 设计原则

1. **所见即所链**：界面是**纵向节点清单**（不是画布），从上到下就是流转顺序；支持插入、删除、上下拖动排序。
2. **零 BPMN 词汇**：界面上不出现"用户任务/网关/顺序流/多实例/监听器/表达式/变量"等术语；用"审批节点/办理节点/抄送/条件分支/参与人/会签"。
3. **配置即弹窗**：每个节点点开一个右侧抽屉完成全部配置，无需在两个页面间来回。
4. **发布即部署**：点"发布"时由**后端**把简化 JSON 编译成 BPMN XML，再调用现有部署链路（`POST /flowable/definition/save`），因此**流程引擎、待办、已办、流转记录、超时任务全部零改动**。
5. **旧设计器不删**：保留为"高级模式（BPMN）"，仅对系统管理员可见，用于复杂分支；简化设计器为默认入口。
6. **在途单据不受影响**：发布生成**新版本**的流程定义；已发起的实例继续跑旧定义。

### 6.2 页面与交互

**入口**：`工作流 → 流程设计（简化版）`，或从模板编辑页"配置流程"直接进入。

| --- | --- | --- | --- |
| **发起**（start） | 流程起点，发起人填写表单 | 可提交范围（全员 / 指定人员 / 指定角色） | 抄送人、发起节点字段权限 |
| **审批**（approve） | 决策节点：同意 / 退回 / 驳回 | 节点名称、参与人来源、多人方式 | 签名策略、可用按钮、字段权限、超时提醒、异常兜底、抄送人 |
| **办理**（handle） | 业务办理（用印、归档、回传），**不做审批结论** | 节点名称、办理人来源 | 签名策略（含"盖章"）、可上传附件、超时提醒、抄送人 |
| **抄送**（cc） | 只通知，无操作 | 抄送人来源 | 抄送时机（到达时 / 通过后） |
| **结束**（end） | 流程终点 | — | 抄送人 |
| **条件分支**（condition，**P0**） | 按表单字段值**选一条**分流（排他） | 分支名称、分支条件（图形化条件组，见 6.3.1） | 分支顺序、兜底分支"其他情况"（**自动生成、不可删**） |
| **并行分支**（parallel，**P0**） | 多支**同时**流转后合流 | 分支数量、合流规则（默认全部完成） | 各分支条件 |

> **两者必须严格区分（PRD 硬约束）**
>
> | 维度 | 条件分支（P0） | 并行分支（P1） |
> | --- | --- | --- |
> | 语义 | 满足条件的分支**只有一条**被执行 | 所有满足条件的分支**同时**被执行 |
> | 兜底 | **必须有**「其他情况」（系统生成、不可删） | **不设**兜底 |
> | 合流 | 天然汇合（排他网关只有一个出口） | 必须显式配置；**默认「全部完成」**（已确认，见下方行为约定） |
> | 典型用途 | 合同类型=经营 → 经发负责人；否则 → 行政链 | 会审部门多选 → 各部门并行会审 |
> | 图标/画法 | 分叉箭头 + 「其他情况」虚线车道 | 并排泳道 + 上下汇合横杠 |
>
> ⚠️ 现状 `conditionPanel.vue:20-24` 把"条件流转路径"做成挂在用户任务出口上的条件，其自带提示写明："**如果该方法选择了多条顺序流，则会生成多个执行，流程会以并行方式继续**"。也就是说：**把条件直接挂在用户任务出口，会让条件分支静默变成并行分支**。因此编译时必须一律经过排他网关（见 6.8）。

**分支与固定节点的行为约定（2026-10-03 业务已确认，冻结）**

| # | 场景 | 结论 | 落地口径 |
| --- | --- | --- | --- |
| Q1 | 并行会审的合流 | **每个被选部门都必须审完**才继续 | 多实例完成条件 `${nrOfCompletedInstances == nrOfInstances}`；"任一完成即继续"降级为**可选配置**，不做默认 |
| Q2 | 某支驳回后其余分支的意见 | **保留留痕** | 其余分支任务置为**已作废**（新增任务状态），`flowCmts` 意见**不删**，办理过程只读可见；驳回理由单独留痕 |
| Q3 | 同一人兼任两个会审部门 | **不合并待办**（产生两个）；**预留配置项**"当审批人为同一人时，是否自动通过" | 设计器节点级开关，**默认"每次都审"**（＝不自动通过）；引擎去重实现与该开关同期交付（P1，REQ-FLOW-006） |
| Q4 | 法务是否强制进流程 | **系统不预置规则**：由**流程管理员在具体流程中固定**（固定节点 / 固定分支） | 系统只提供"固定节点"能力；合同审批模板中法务为**主链固定审批节点**，且提交人"其他会审部门"多选**不含法务** |

> **Q4 的设计含义**：系统**不内置**"哪些合同必须法审"的判断逻辑（不写字典规则、不做金额/类型硬编码），只提供"把某个节点固定进流程"的能力。这样同一套代码既能表达"合同必送法务"，也能表达"另一类单据不送法务"，切换只改流程配置、不改代码。
>
> **连带实现项**：① 新增任务状态「已作废」（Q2）；② 打印件中"已作废"分支的签批栏**仍打印并标注"（已作废）"**（只有"未到达"节点才是空栏）；③ 待办列表不显示已作废任务。

> **合同审批流程形状（2026-10-03 确认）**——法务为主链**固定必经节点**，会审并行只承载"由提交人勾选"的部门：
>
> ```
> 发起 → ① 责任部门审批 → ② 法务（固定必经）→ ③ 会审部门（并行：经营/经济/人力/行政，按勾选）
>      → ④ 集团分管领导 → ⑤ 集团董事长 → ⑥ 用印办理 → 结束
> ```
>
> "要不要送法审"由**管理员在流程配置里**决定（把节点放进去 / 拿掉），系统不预置规则；提交人的「其他会审部门」多选**不含法务**。

### 6.3.1 图形化条件组组件（REQ-DESIGN-010）

> 这是"条件分支"的唯一配置入口。目标：业务管理员**不写一行代码**就能表达"当 A 且 B，或 C 时走这条分支"。

**组件构成**：`条件组（组间「或」）` → `条件行（组内「且」）` → `字段 / 比较符 / 值` 三件套。

**可用字段 × 比较符矩阵**

| 字段类型 | 可用比较符 | 值的输入控件 |
| --- | --- | --- |
| 单选 | 等于 / 不等于 / 属于 / 不属于 | 选项多选 |
| 多选 | 包含任一 / 包含全部 / 不包含 / 为空 / 不为空 | 选项多选 |
| 单行文本 | 等于 / 不等于 / 包含 / 不包含 / 为空 / 不为空 | 文本 |
| 数字 / 金额 | 等于 / 不等于 / 大于 / 大于等于 / 小于 / 小于等于 / 介于 / 为空 | 数字（介于时两个框，带单位与千分位） |
| 日期 / 日期时间 | 等于 / 早于 / 晚于 / 介于 / 为空 | 日期选择 |
| 日期区间 | 包含某日期 / 与区间相交 / 完全包含于 / 为空 | 日期区间选择 |
| 部门 | 属于 / 不属于 / 包含下级 / 为空 | 组织选择器 |
| 选人 | 包含 / 不包含 / 为空 | 人员选择器 |
| 提交人（系统内置） | 属于某部门 / 不属于某部门 / 等于某人 | 组织 / 人员选择器 |
| 流水号 / 附件 / 上传 / 说明文字 / 分组标题 | **不可作为条件** | — |

**五条硬约束**

1. **只列必填字段**：下拉里只出现表单中设为"必填"的字段；非必填字段置灰并提示"先到表单设计设为必填"。原因：字段可空 → 条件可能恒假 → 单据静默落入兜底分支。
2. **没有表达式框、没有脚本**：不提供自由文本比较符，不允许输入字段名或编码（现状 `conditionPanel.vue:33-50` 的表达式/脚本入口在本设计器中**禁用**）。
3. **选项类字段按 label 比较**：提交时选项已转成中文 label 写进流程变量（`BizFormServiceImpl.java:219-267,430-461`），因此条件里的值也用 label，编译与求值口径统一。
4. **实时自然语言回显**：面板顶部把当前条件翻成一句话，例如
   `当 (合同类型 等于 经营) 或 (合同金额 大于 500000) 时，进入本分支` —— 这是防"且/或 理解错"的关键交互（原型 S18）。
5. **求值是排他的**：按分支顺序取**第一条为真**的分支；因此**分支顺序即优先级**，设计器支持拖动调整分支先后。

**边界**

| 项 | 本期 |
| --- | --- |
| 条件组数 / 每组条件行数 | 各 ≤5 |
| 分支数 | ≤5（V-10） |
| 嵌套条件分支 | 不支持（V-11） |
| 跨字段计算、脚本、外部数据源 | 不支持 → 引导到「高级模式（BPMN）」 |

**运行期**：编译为 `exclusiveGateway` 的出口条件表达式；条件全部为假时走 `default` 流（=「其他情况」分支），保证单据不卡死。

### 6.8 与 BPMN / Flowable 的映射（技术口径）

| 简化概念 | BPMN / Flowable 产物 |

| 签名策略 | `userTask` 扩展属性 `signMode/signTypes` |
| 超时提醒 | `boundaryEvent` 定时器 + 已有的 `FlowTaskTimeOutListener` + `t_workflow_timeout_job` |

> ⚠️ **编译硬约束（必须写成单测）**
>
> 1. **条件分支一律编译成 `exclusiveGateway`**，条件写在网关的出口顺序流上，兜底走网关的 `default` 属性。
> 2. **禁止把条件直接挂在 `userTask` 的多条出口顺序流上**。BPMN 原生语义下，多个条件同时为真会**生成多个执行并以并行方式继续**（证据：本项目 `UI/components/Process/panel/conditionPanel.vue:11-13` 的官方提示原文）。这样会让"条件分支"静默退化成"并行分支"——用户以为只走一条，实际多条同时产生待办。
> 3. 单测：构造"两条分支条件同时为真"的流程定义，断言运行时**只产生一个待办**；断言兜底分支在条件全部为假时被选中。

**兼容**：`t_template.def_key` 仍指向流程定义 key，**模板配置链路零改动**；旧 BPMN 流程定义继续可用（高级模式维护）。

### 6.9 迁移与灰度

1. 新流程一律用简化设计器；存量流程定义**不迁移**（BPMN 设计器保留为高级模式）。
2. 简化 JSON 与 BPMN XML **双向不保证可逆**：若某流程被"高级模式"改过，简化设计器对该流程转为**只读**并提示"该流程已在高级模式中修改，如需继续用简化版请复制为新流程"。
3. 灰度：先给集团流程管理员开放；连续 2 周无阻断问题后开放给子公司流程管理员。

## 第7章 需求二：表单打印

### 7.1 目标与场景

| 场景 | 谁打印 | 要求 |
| --- | --- | --- |
| 用印前打印交领导手签 | 发起人 / 用印办理人 | 版式与纸质流转单一致，签批栏空白可手写 |
| 审批完成后打印归档 | 发起人 / 档案管理员 | 含全部审批意见与签名，A4 单页为主 |
| 审计/检查补打 | 审计人员 | 与首次打印内容一致，且**可追溯谁在何时打印过** |
| 对外提供 | 业务人员 | 导出 PDF，带防伪水印 |

**不变量**：打印是**只读动作**，不得改变任何业务数据；打印内容与打印时刻的单据状态一致（打印后再审批，重新打印要反映出新状态）。

### 7.2 打印入口与流程

```
入口1 单据详情页（pageType=2）右上角 [打印]
入口2 待办/已办/我起草 列表行操作 [打印]
入口3 打印预览页直链 /workflow/print?businessId=xxx&templateId=yyy（需登录鉴权）
        │
        ▼
新窗口打开「打印预览页」
        │  加载：GET /workflow/print/data/{businessId}
        ▼
渲染 A4 版式（HTML+CSS）──▶ [打印] window.print()  ──▶ 浏览器打印对话框
                        └──▶ [导出 PDF]（本期=浏览器"另存为 PDF"）
        │
        ▼
写打印日志 POST /workflow/print/log（打印时间/人/IP/页数）
```

**页面元素**：`[打印]`、`[关闭]`、`[刷新数据]`、页数提示"共 X 页"、模板名（P1 可切换多个打印模板）。

### 7.3 技术实现（本期口径）

| 决策 | 内容 | 理由 |
| --- | --- | --- |
| 渲染方式 | **纯 HTML + CSS 打印**（`@page { size: A4 portrait; margin: 12mm 10mm; }` + `@media print`） | 零新依赖、可控、离线可用 |
| 不引入 hiprint | `vue-plugin-hiprint@0.0.56` 虽已在 `package.json`（`UI/package.json:65`）但全库零引用；本期**不用**，留作 P1 可视化模板 | 避免为"打印一张表"引入模板引擎与额外运行时 |
| 样式隔离 | 打印页独立样式文件 `print-a4.scss`，不使用 Element 主题变量、不使用 flex 打印差异大的布局 | 规避各浏览器打印差异 |
| 字体 | 优先 `SimSun/宋体`、`SimHei/黑体`，字号用 `pt`（如 10.5pt≈五号） | 打印稳定；不依赖 webfont |
| 数据获取 | 新增聚合接口（见 10.2），一次拿齐 表单+节点+意见+签名+附件 | 避免打印页发 5 个请求 |
| 不依赖 | **不依赖 kkFileView、不依赖 LibreOffice** | 规避 P-7 |
| 导出 PDF | 本期用浏览器"另存为 PDF"；P1 提供后端 PDF 渲染与"打印件归档" | 成本/收益 |

### 7.4 打印内容与版式

版式自上而下 5 个区：

**A. 抬头区**

```
┌────────────────────────────────────────────────────────────┐
│ [Logo]        集团合同类文件流转审批单              [二维码] │
│                                            单据编号 HT2026… │
├────────────────────────────────────────────────────────────┤
```
- 标题文本模板可配（默认"集团合同类文件流转审批单"）。
- 二维码内容：单据详情 URL（扫码可查，需登录）；可关闭。

**B. 基本信息区**：表格（标签-值），支持单元格跨列/跨行；字段与排版由 `field_map` 决定（7.7）。

**C. 签批栏区（核心，按流程节点动态生成）**

```
┌───────────────────────────────────────────────────────────────────┐
│ ① 责任部门审批                                                    │
│ 接收单位：经发部      接收人：郑妍        签收时间：2026-07-24 09:12│

├───────────────────────────────────────────────────────────────────┤
│ ② 会审部门（经济）                                                │

│ 处理意见：已做合同台账管理。                                       │
│ 签名：[签名图片]                                                  │
└───────────────────────────────────────────────────────────────────┘
```
规则：

| 规则 | 说明 |
| --- | --- |
| 节点来源 | 按**流程定义的节点顺序**生成，与设计器序号 ① ② ③ 一致 |
| 出栏节点 | 审批节点、办理节点出栏；抄送节点可配（默认不出栏） |
| 接收人/接收单位 | 任务办理人 / 其所属部门（`flowRecord`） |
| 签收时间 | 任务创建时间（`flowRecord.createTime`） |
| 处理意见 | `flowCmts` 的 `comment`，支持换行、限 500 字 |
| 签名 | 该任务对应的 `t_workflow_sign_record.file_id`，等比缩放后右对齐 |
| 未到达节点 | 整栏留空（或打印"未到达"浅色字，模板可配） |
| 会签多人 | 同栏内按人分行（人/时间/意见/签名各一行） |
| 退回/驳回 | 显示为 `退回（至 XX 节点）` / `驳回（理由…）`，并保留原签批内容 |

**D. 附件清单区**：序号 / 附件名 / 上传人 / 上传时间 / 大小（**不打印文件内容**）。

**E. 页脚区**：`打印时间：yyyy-MM-dd HH:mm ｜ 打印人：XXX ｜ 第 X 页 / 共 Y 页`；可选防伪水印文字。

## 第8章 需求三：签名组件（选配）

### 8.1 概念与边界（先分清四件事）

| 概念 | 作用对象 | 表现形式 | 用途 | 现状 |
| --- | --- | --- | --- | --- |
| **手写签名** | 单据（本 PRD 新增） | 审批人现场手写，PNG 图片 | 审批人"个人确认" | **无业务入口**（PDF 层有 `PdfService.signature`） |
| **预存签名** | 单据 | 个人预先保存的签名图片，一键调用 | 高频审批提效 | 无 |
| **电子印章（盖章）** | **正文 PDF** | 公章 / 合同章 / 发票章 | 组织用印 | **已有**：`PdfService` + `t_workflow_main_seal` + `POST /workfile/main/stamp` |
| **免签** | 单据 | 不签名，仅意见 | 低风险节点 | 现状即如此 |

> **关键区分**：签名 = **人**；盖章 = **组织**。签名落在**单据（打印件）**上；盖章落在**正文文件**上。两者可同时要求（用印办理节点）。

### 8.2 节点级签名策略（设计器配置项）

| 配置项 | 取值 | 默认 | 生效点 |
| --- | --- | --- | --- |

### 8.5 签名记录与不可篡改

```sql
CREATE TABLE t_workflow_sign_record (
  id             varchar(64)  NOT NULL COMMENT '主键',
  business_id    varchar(64)  NOT NULL COMMENT '业务ID',
  proc_ins_id    varchar(64)  DEFAULT NULL COMMENT '流程实例ID',
  task_id        varchar(64)  DEFAULT NULL COMMENT '任务ID',
  task_def_key   varchar(64)  DEFAULT NULL COMMENT '节点定义key',
  node_name      varchar(200) DEFAULT NULL COMMENT '节点名称（=打印件签批栏标题）',
  sign_type      char(1)      NOT NULL COMMENT '签名方式，0-手写，1-预存，2-印章',
  file_id        varchar(64)  DEFAULT NULL COMMENT '签名图片文件ID（sign_type=2 时为盖章后文件ID）',
  sign_user_id   varchar(64)  NOT NULL COMMENT '签名人ID',
  sign_user_name varchar(50)  DEFAULT NULL COMMENT '签名人姓名',
  sign_time      datetime     NOT NULL COMMENT '签名时间',
  sign_ip        varchar(64)  DEFAULT NULL COMMENT '签名IP',
  user_agent     varchar(500) DEFAULT NULL COMMENT '浏览器UA',
  form_data_hash varchar(64)  DEFAULT NULL COMMENT '签名时表单数据 SHA-256',
  prev_hash      varchar(64)  DEFAULT NULL COMMENT '上一条记录哈希',
  record_hash    varchar(64)  NOT NULL COMMENT '本条记录哈希',
  PRIMARY KEY (id),
  KEY idx_biz (business_id),
  KEY idx_task (task_id)
) COMMENT='签名记录表（只追加）';
```

| 规则 | 说明 |
| --- | --- |
| 只追加 | 数据库触发器拒绝 `UPDATE` / `DELETE`（与现有不可变审计同思路） |
| 哈希链 | `record_hash = SHA256(id‖business_id‖task_id‖file_id‖sign_user_id‖sign_time‖form_data_hash‖prev_hash)`，`prev_hash` 取同单据上一条 |
| 表单快照 | `form_data_hash` = 签名时刻 `t_workflow_form.form_data` 的 SHA-256，用于证明"签的是哪一版内容" |
| 重签 | 不允许改旧记录；撤销签名 = 追加一条"撤销"记录并在业务上作废 |
| 加签/转办 | 新办理人**重新签名**，不继承原签名 |

### 8.6 与审批动作的关系

```
填审批意见 → [可选/必需] 签名 → 提交（同意 / 退回 / 驳回）
                                  │
                                  ├─ 同意：签名记录 + 任务完成
                                  ├─ 退回/驳回：即使节点要求"必需签名"也允许无签名提交，
                                  │            但必须写审批留痕（不写签名记录）
                                  └─ 签名策略=必需 且 未签名 且 动作=同意 → 阻断
```

- 签名**先于**提交落地；提交失败时签名记录保留（标记为"未随单生效"由后续流程状态判定，或直接作废）。
- 会话超时/重复提交：以 `task_id + sign_user_id` 做幂等。

### 8.7 打印呈现

- 打印件签批栏内嵌签名图片；按栏高（默认 24mm）等比缩放，右对齐（模板可配居中）。
- 无签名：留空栏（供手写）；`签名要求=不需要` 的节点可打印"（免签）"小字（可配）。
- 会签多人：每人的签名落在各自那一行。

### 11.6 可维护性

- 简化流程 JSON 带 `schemaVersion`，便于后续演进。
- 打印模板 `field_map` 与表单字段解耦：字段改名（`__vModel__` 不变）不影响打印。
- 所有新增表带 `create_time/update_time`，遵循既有命名规范（`t_` 前缀、`char(1)` 布尔）。
