## 2. ① 全局主题色统一

### 2.1 关键认知：主题色是**三处耦合**，只改一处会出现"两套蓝"

| 位置 | 角色 |
| --- | --- |
| `src/assets/styles/element-variables.scss` 的 `$--color-primary` | Element UI **编译期**主题 |
| `public/styles/theme-chalk/index.css` | `ThemePicker` 运行时拉取并整体重着色的静态 CSS |
| `src/components/ThemePicker/index.vue` 的 `ORIGINAL_THEME` | 重着色算法的**锚点**，必须等于上表那份 CSS 里实际写死的主色 |
| `src/store/modules/settings.js` 的默认 `theme` + 旧值迁移 | 否则老用户 localStorage 里的旧色会把品牌蓝刷回去 |

### 2.2 又一个关键认知：**运行时换色只在 dev 有效**

`ThemePicker` 是靠改写内存里的 `<style>` 标签实现的。生产构建的 CSS 走 `<link>`，改不到。
所以在 dev 下"看起来已经统一了"是**假象** —— 必须做源码级替换。

### 2.3 实际改动

| 范围 | 处理 |
| --- | --- |
| `element-variables.scss` | `$--color-primary: #1890ff` → `#1f5ae0` |
| `ThemePicker/index.vue` | `ORIGINAL_THEME` → `#1f5ae0`；调色板预置色首位加品牌蓝 |
| `settings.js` | 默认主题 → `#1f5ae0`；`LEGACY_THEMES`（`#409eff`/`#1890ff`，大小写无关）迁移到品牌蓝 |
| `public/styles/theme-chalk/index.css` | 整个色簇重映射（主色 + tint 0.1~0.9 + shade 0.1）：**142 处 `409eff` → 0**，共替换 180 处 hex |
| `src/components/vform/VFormDesigner.css`（第三方预编译产物） | 176 处 hex + 51 处 `rgba(64,158,255,…)` 一并重映射 |
| 源码裸色值 | **93 处**：87 处脚本批量、3 处脚本漏掉后手工补、3 处刻意保留（见下） |

## 3. ② 前端错误态覆盖

### 3.1 先说一个容易做错的前提

仓库里有 **71 处 `.catch(() => {})`**，但**不能一律当成 bug**：

- 其中相当一部分接的是 `this.$confirm(...)` 的 **"用户点了取消"** —— 那是正常控制流；
- 真正的缺陷是**一个 catch 同时吞掉了「用户取消」和「请求失败」**，导致点了发布/删除没反应也没报错。

所以本轮的做法是**拆开两条路径**，而不是无脑删 catch。
另外 `src/utils/request.js` 的行为也决定了文案怎么写，见 3.3。

### 3.2 新增两件基础设施

| 文件 | 作用 |
| --- | --- |
| `src/components/StateBlock/index.vue` | 四态面板（loading / empty / error / ready），带 `compact` 紧凑模式供首页小卡片用 |
| `src/utils/errorMessage.js` | `describeError(err)` → `{text, cause}`，把 axios / request.js 的错误翻译成「发生了什么 + 为什么」 |

`StateBlock` 按 `doc/skills/open-design/craft/state-coverage.md` 实现，内置：

- 加载超过 **15s** 出现「比预期更久」兜底提示（不让转圈无限转）；
- **重试纪律**：第 1 次立即，之后 2s / 4s / 8s 退避，按钮冷却倒计时；
- 满 3 次后**不再给"重试"**，改为「请把错误编号提供给管理员」+ 可复制的**错误编号**；
- 显示「上次尝试：X 秒前」并自动走字；
- 常驻 `aria-live` 播报区（**必须先在 DOM 里**，否则与内容同时插入不会触发朗读）、`role="status"`/`role="alert"`；
- 错误文案 `word-break` + `overflow-wrap: anywhere`，超长信息不撑破布局（极端值）。

### 3.3 `describeError` 必须知道 `request.js` 的两件事（否则一定写错）

1. **HTTP 层错误**走 error 拦截器，它把 `error.message` **改写成中文**：
   `"Network Error"` → `"后端接口连接异常"`、含 `timeout` → `"系统接口请求超时"`、
   `"Request failed with status code 404"` → `"系统接口404异常"`。
   → 所以 `/timeout/i`、`message === 'Network Error'` 这类**英文判定永远不会命中**。
2. **业务码错误**走 response 拦截器的 reject，且 **reject 的值可能是字符串而不是 Error**：
   `code 401` → 一个**可读中文串**；`code 601` 与其它非 200 → 字符串 `'error'`（不含任何信息）。
   → 直接把 `'error'` 显示给用户毫无意义；而丢掉 401 那条可读串则是更严重的缺陷。

## 4. ③ 画布拖拽排序

- `vuedraggable` 2.24.3 / `sortablejs` 1.10.2 已在 `node_modules`，**未新增依赖、未改 `package.json`**。
- `<draggable :list="nodes">` 直接绑 `flow.nodes` / `br.nodes`（`alterList()` 原地 `splice`，所以保存草稿序列化出来就是新顺序）。
- 每个 `v-for` 迭代包成单个 `.ft-item`（卡片 + 泳道 + 连接点），否则 draggable 的 item 索引会算错。
- **只允许同链**：`group.name = 'ft-chain-' + _uid`（每实例唯一）。
- **起止节点是锚点**：`filter` 挡一道 + `@start` 记下标、`@end` 按**对象身份**摘掉再按原下标插回（越界钳到末尾）。
- **选中态重解析**：选中用的是**下标路径**，重排后下标必变。`reorderStart()` 按引用记下当前选中对象与已折叠泳道对象，`reorderEnd()` 用 `findPathOf()` 遍历整树按身份写回 `selection.path` 与 `collapsedLanes`。
  不这么做会**静默打开另一个节点的配置面板**、或"另一条泳道莫名其妙是收起的"。
- 删掉了 ↑↓ 按钮及 `moveNodeAt()`/`provide.moveNode`（全仓库 grep 确认零引用）；泳道头的「前移/后移」保持原样。

## 10. 本轮新增的坑（供下次避雷）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| **主题色三处耦合** | 只改 `element-variables.scss` 后颜色仍是若依蓝 | 见 §2.1；`ThemePicker` 的 `ORIGINAL_THEME` 是"锚点"不是"当前色" |
| **运行时换色只在 dev 有效** | dev 看着已经统一，生产构建后又是旧色 | 必须做源码级替换；页面里不要写裸色值 |
| **SVG 的 `fill` 不接受 `var()`** | 图标颜色不生效 | `fill` 是表现属性，给字面量色值 |
| **`public/` 静态资源没有 HMR** | 改了 `theme-chalk/index.css` 不生效 | 重启 dev server |
| **全局正则的 `lastIndex` 状态** | 用 `/x/g` 反复 `.test()`，结果在奇偶次调用间跳变，批量替换静默漏掉 3 处 | 批量替换脚本里不要复用带 `g` 的正则做 `.test()` |
| **`getThemeCluster` 的第 0 项是裸 hex** | 离线复刻色簇替换时基色一处都匹配不到 | 簇的第 0 项是 `clusters[0] = theme`（无 `#`），其余 tint/shade 自带 `#` |
| **`request.js` 会把错误 message 改写成中文** | 按英文关键词判定超时/网络永不命中 | 见 §3.3 |
| **`request.js` 的 reject 值可能是字符串** | 401 的可读中文串被当成"没有 message"丢掉 | 先判 `typeof err === 'string'` |
| **`.catch(() => {})` 不都是 bug** | 其中不少在吞 `$confirm` 的"用户取消" | 要拆路径，不要无脑删 |
| **手工删 Flowable 部署后不重启后端** | 引擎缓存与库不一致 | 见 §7 |
| **PowerShell 传 `-h127.0.0.1`** | mysql 报 `Unknown MySQL server host '127'` | 用 `--host=127.0.0.1` |
| **探针路径可能撞上既有路由** | 想用"改错接口地址"验证错误态，结果 `/simple-flow/list-XXX` 命中了 `GET /{id}` 返回 200，验证无效 | 探针要用肯定不存在的路径（如 `/workflow/__no_such_module__/list`） |
