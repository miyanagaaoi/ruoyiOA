## 1. 一句话

按原型图的**四个分组**（申请详情 / 合同有效期 / 我方信息 / 对方信息）做骨架，
把 PRD §7.8 要求打印出来的**每一个表单字段**补齐（合同编号、扫描件编号、签订时间、附送材料、其他会审部门…），
控件一律用**系统已有**的（不新造控件），并把流程条件/并行会审需要的字段设成**必填 / 多选**。

## 3. 与原型的差异（都是有据的）

| 原型图 | 落地 | 依据 |
| --- | --- | --- |
| 「合同类型」出现两次 | 第二次改名「合同类别」 | PRD §4.2 原文明写"原图重复，落地只保留 1 个「合同类型」，另一个改为「合同类别」或删除" |
| 「签订公司」是单行文本 | 改为**组织选择**（`design-dept-select`） | PRD §4.2 原文明写"建议改为组织选择，默认取发起人所属公司" |
| 附件 * / 盖章备案上传 | **未做成表单字段**，改为说明文字 | 表单设计器自己的提示："请不要使用上传组件，模板配置中已提供单独的页签存放附件" ⇒ 附件走模板的附件页签，不塞进表单 |
| 「时长（天）」手填 | 只读计算 `design-calc` | PRD §4.2「要点」② |
| （原型没有）合同编号 / 扫描件编号 / 签订时间 / 附送材料 / 责任部门 / 其他会审部门 / 用印备案编号 | **补上** | PRD §7.8 打印映射表要求这些栏目有表单来源（否则打印件对应行永远为空） |

## 4. ⚠ 两个不能想当然改的地方

1. **`field101` 不能改名成 `contractType`。**
   已发布流程 `testCondition` 的排他分支条件写的是 `field101 = 经营 / field101 = 经济`
   （见 `t_flow_simple.content`）。改 vModel 会让条件指向不存在的字段 ⇒ 发布校验 V-8 直接拦。
   所以「合同类型」沿用 `field101`，另给「合同类别」（`contractCategory`）放自由分类。
2. **`amount` 必须必填。**
   PRD §7.8 第 10 项要"合同金额 + 大写"，而 §6.3.1 规则①要求**条件字段必须已设为必填**
   （非必填字段在条件下拉里是置灰的）。金额必填之后，将来要加"金额 > 10000 走分管领导"这类分支才立得住
   （这正是存量缺陷清单里的待定项：`doc\缺陷-流程条件字段与关联表单错位.md` §7-A 说"金额未设必填 ⇒ 分支2 只能用 field101"）。

## 5. 怎么用（模板已建好，见 §5.1）

1. **模板配置 → 新增模板**：表单选「合同审批（含用印）」，分类随意；
2. 模板绑定一个流程定义 → 这样「新启流程」里才会出现这张单；
3. 打开该模板的**「流程设计」页签**，在设计器里点「条件分支 → 字段」，
   下拉里应能看到上面 8 个必填字段（含 `amount` ⇒ 可以直接做金额分级）；
4. 并行会审：把「并行分支」的「表单字段」选 `jointDepts`（多选）—— 勾几个部门就生成几个会审任务。
