## 2. 内置版式（4 套）

由**单据模板**上的 `t_template.builtin_print_key` 选择，取值与栏目如下（栏目文案即打印件上的栏目，逐项对应 PRD 附录 A）：

| key | 名称（= 打印件标题） | 栏目 |
| --- | --- | --- |
| `contract` | 集团合同类文件流转审批单 | 提报单位 / 报送人 / 报送时间 / 合同编号 / 合同全称 / 合同签订主体-甲方 / 合同签订主体-乙方 / 合同金额 / 履约开始 / 履约结束 / 合同签订时间 / 其他会审部门 / 相关说明；签批栏**按流程节点动态出栏** |
| `fund` | 集团资金审批单 | 审批单位 / 事项分类 / 计划类别 / 付款归属期 / 资金审批内容；签批栏固定三栏**集团职能部门 / 集团分管领导 / 集团董事长** |
| `matter` | 集团事项类打印审批单 | 公文来源-报送单位 / 报送人 / 报送时间 / 文件编号 / 信息名称 / 文件类型 / 加急程度 / 文件概要；签批栏固定七栏（公文接收及处理 / 公文关联单位处理 / 集团领导意见-分管领导 / 集团领导意见-总经理 / 集团领导意见-董事长 / 印鉴证照管理部门 / 公文回传及归档） |
| `payment` | 付款申请单 | 日期 / 计划内-计划外 / 收款单位名称 / 开户银行 / 账号 / 付款单位名称 / 开户行 / 一级分类 / 二级分类 / 付款归属期 / 结算方式 / 回单 / 银行付款用途 / 付款事由 / 金额 / 金额大写 / 备注；签批栏固定六栏**经理 / 财务 / 部门负责人 / 财务负责人 / 制单人 / 领款人**（制单人取发起人） |

**关键取值口径**：

- `合同金额` / `金额` 走表单控件 `design-amount`，渲染成 `1,234.56（人民币壹仟贰佰叁拾肆元伍角陆分）`；
- `金额大写` 是**只取大写**的独立栏目（`format: amountUpper`），与「金额」共用 `utils/money.js`，二者**永远一致**（AC-36）；
- `审批单位` / `公文来源-报送单位` 取 **`$submitterCompany`**（发起人所属**公司级**部门，由 `sys_dept.ancestors` 上溯；本部门已是公司级时取它自己）。新增的 `$submitter` / `$submitterDept` / `$submitterCompany` 三个内置变量都来自**单据发起人**（`t_workflow_form.create_id` → `sys_user` → `sys_dept`），因为流程记录里的 `start_user_name` / `start_dept_name` 在 ruoyi-flowable 里**从不赋值**（实测恒为 null）；
- 固定栏目的签名区按**节点名**匹配流程节点；**匹配不到也照样出栏**（留空供手写）——纸质表单上那几栏是印好的，不出栏才是错的。

### 2.1 排版路径（一个刻意的例外）

| 生效模板 | 字段区怎么排 |
| --- | --- |
| 自定义模板（`t_template_print_template.id` 有值） | 按它自己的 `field_map`；留空则按单据表单字段自动排版 |
| 内置 `fund` / `matter` / `payment` | **按版式常量**（为固定纸质表单定制的栏目） |
| 内置 `contract` | **保持升级前的"按表单 schema 自动排版"**（表单字段为空时才用版式常量） |

> 为什么 `contract` 例外：存量模板的 `builtin_print_key` 都取默认值 `contract`（实测 9/11 个启用模板没有自定义打印模板）。
> 若让它一律按 13 行合同映射排版，那些自定义表单字段（金额/说明…）会从打印件上**整片消失** —— 那正是 AC-61「存量模板零回归」要防的事。
> 这个判定收在 `src/views/workflow/print/printLayout.js#useBuiltinLabelLayout`，有前端用例覆盖。

## 3. 生效打印模板的优先级链（**未变**）

```
显式 printTplId  >  该单据模板下的启用行  >  内置版式（按 builtin_print_key）
```

- 同一单据模板下**只保留一套启用**（启用新的会自动停用旧的）—— 这是服务端不变量，不取决于"谁最近被改过"；
- 只要**有一套启用的自定义模板**，内置版式就**不参与**该单据的打印（配置页会显式提示这一点）；
- 未登记的 `builtin_print_key`（人工 SQL 写脏）**不抛异常**，回退 `contract` 并记一条 warning：打印是收尾的只读动作，为一个脏值让整张纸打不出来，比版式降级更糟。**保存入口会拒绝非法 key**，所以脏值只能来自人工改库。

## 4. 配置页怎么用（「打印模板配置」）

入口：**流程管理 → 打印模板配置**。页面顶部选「单据模板」，下面就是两种模式。

### 4.1 「选择内置模板」

1. 在「内置版式」下拉里选一套（`contract` / `fund` / `matter` / `payment`）；
2. 点「保存版式选择」→ 写的是**单据模板**的 `builtin_print_key`（只改这一列）；
3. 点「预览该版式栏目」→ 立刻在「实时预览」里看到该版式的标题、栏目、签批栏栏目、纸向与各区开关。

> 若该单据模板下已有**启用的自定义模板**，页面会给出黄色提示：内置版式目前不参与打印，保存版式选择也不会改变打印结果。要改用内置版式，请先停用/删除那套自定义模板。

### 4.2 「选择自定义模板」

- 「新增打印模板 / 修改」对话框里可配：名称、单据标题、**纸张（A4/A3）**、**方向（纵向/横向）**、签批栏/意见/附件清单/抄送节点出栏/水印五个开关、**Logo 上传**、页脚备注、字段映射 JSON、启用状态；
- **「填入内置版式」**：下拉选一个版式键，内容由后端接口
  `GET /workflow/print/defaultFieldMap/{builtinKey}` 返回。
  **调整版式只需要改后端一处，无需重新构建前端**（REQ-PRINT-013）；
- 表格里「生效中」标记唯一启用的一套；「停用/启用」改变该单据的生效模板。

### 4.3 实时预览

「实时预览」区直接列出当前生效模板的**标题 / 纸张与方向 / 签批栏 / 附件清单 / 栏目清单 / 签批栏栏目**，不用先存再打一张才知道配成了什么样。

### 4.4 Logo 上传注意

- 走**经典上传链路** `POST /common/upload`（字段名 `file`），落库的是**相对路径**（如 `/profile/upload/2026/10/05/xxx.png`）；
- 打印件用 `VUE_APP_BASE_API` 前缀取图；**不加前缀**那个地址由前端 dev server 接管，返回的是 SPA 的 HTML（200 但不是图片）；
- ⚠ **不要**用新文件模块 `/file/operate/**`：它的本地路径是 `E:/ruoyi/upload`，与本机真正有文件的 `F:/dsh/ruoyiOA/uploadPath` 不是一回事（`DEV-ENV.md` §6.20）。

## 5. 签批栏与附件清单：由**配置值**决定，与"是否内置"无关

**这是一处有意的行为变更（AC-62 的第一验收项）**：

- 升级前客户端把内置模板的 `showSignature` / `showAttachment` **强制置 false**，于是《集团资金审批单》"看着配好了、打出来没有签名区"（PRD 风险 R-3）；
- 现在一律读生效模板的配置值。四套内置版式**自带"签批栏开启"**的推荐取值（`fund`/`matter`/`payment` 的栏目里本来就有按节点生成的签名栏），附件清单维持"显式打开"的既有定位。

### ⚠ 存量打印件的人工确认要求

**升级后走内置版式的存量打印件会新增签名区**（因为内置版式自带了签批栏开启）。这是**有意**的修正，但属于用户可见的变化，因此交付时要求：

1. 找出仍走内置版式的存量单据模板（`builtin_print_key='contract'` 且该模板下没有启用的自定义打印模板）；
2. **逐张**打印确认新打印件符合预期（尤其确认签名区不是"多出来一栏不该有的东西"）；
3. 把结论记入验收记录。若某张单据确实不该出签名区：给它建一套自定义打印模板并把签批栏关掉，或把该模板的 `builtin_print_key` 指向更合适的版式。

另：`show_signature` / `show_attachment` 的**默认值语义已统一**——DDL 默认与 `fillDefaults` 的空值口径都是 `'0'`（"只打印表单信息"），因此"直插库"与"走接口"两条写入路径结果一致（升级前 DDL 默认 `'1'`、代码填 `'0'`，两条路径行为不同）。**已落库的存量行不受影响**（它们有显式值）。

## 6. 纸张与方向、抄送栏

- **纸张与方向**：读生效模板的 `paper` / `orientation`；未配置或取值不认识时按 **A4 纵向**渲染。页数测算沿用"按像素测算"的既有路线（不依赖 CSS `counter(pages)`，避免浏览器差异），只是把原先硬编码的 A4 版心高度换成按纸张与方向算出来的值 —— 所以 A3 横向的「第 X 页 / 共 Y 页」不会再按 A4 算；
- **抄送栏**：模板 `showCcNode='1'` 且流程存在抄送记录时输出（节点 / 抄送人 / 抄送时间 / 阅办状态）。
  抄送在本项目里是一条 `handle_type='6'` 的只读待办，存在 `t_workflow_todo`；**已阅办的记录仍在同一张表**（`read_flag='1'`），所以出栏时能看全，不会随着"已阅"逐渐消失。

## 8. 打印留痕是**硬门禁**

点击「打印」的顺序是：**测页数 → 写留痕 → 成功才调起打印**。

- 留痕写入**失败时不会打印**，页面弹出：
  > **打印留痕写入失败，请联系管理员**
- 为什么这么严：打印这个动作一旦发生就**物理上无法回滚**，而审计要求"必留痕"。升级前是"先打印、后补日志、失败只 warning"，等于留痕可有可无；
- 代价（已接受的取舍）：留痕服务不可用时用户**打不出纸**。提示文案明确写了"联系管理员"，避免用户误以为是浏览器问题；
- 留痕内容以**服务端会话**为准：打印人取登录身份（不接受客户端传入），打印 IP 与 User-Agent 由服务端从请求里提取；对单据没有查看权时返回 403 且**不落库**。

## 9. 接口一览（B2）

| 方法 | 路径 | 用途 | 权限点 |
| --- | --- | --- | --- |
| `GET` | `/workflow/print/builtinTemplates` | 内置版式清单（key + 名称 + 签批栏/附件清单推荐取值） | `workflow:print:template` |
| `GET` | `/workflow/print/defaultFieldMap/{builtinKey}` | 内置版式字段映射（**唯一真源**，未知 key 回退 `contract`） | `workflow:print:template` |
| `POST` | `/workflow/print/builtinKey` | 保存单据模板的内置版式键（body：`{templateId, builtinKey}`） | `workflow:print:template:edit` |
| `GET` | `/workflow/print/data/{businessId}` | 打印数据聚合（**V1 既有，契约仅删掉死字段 `formSchema`**） | 查看权（服务端判定） |
| `GET` | `/workflow/print/template/{templateId}` | 生效打印模板（含内置；`?printTplId=` 可显式指定） | 登录 |
| `POST` | `/workflow/print/log` | 写打印留痕（只追加） | 查看权（服务端判定） |

> `POST /workflow/print/builtinKey` 是对 PRD §9.3 接口清单的**一处新增**，理由：REQ-PRINT-018 要求"配置页选择内置模板 → 保存后该单据模板的 `builtin_print_key` 为该键"，而复用 `PUT /workflow/template` 有两个硬伤 ——
> ① 那条链路是 `TemplateDTO` 的**全量**回写（MapStruct 默认把未提交字段置空），从打印配置页发一次"只改版式键"的请求会把单据模板的其它字段一起打掉；
> ② 它要求 `workflow:template:edit`，而本页按钮的权限是 `workflow:print:template:edit`，会出现"页面上能点、点下去 403"。
> 所以给了一个**只改一列**、权限点与本页一致的窄接口。**没有新增权限点、没有新增菜单**（design D10）。

### 9.1 示例请求（带 token 可原样执行）

```powershell
$token = (Get-Content .\.cache\token-superAdmin.txt -Raw).Trim()
$h = @{ Authorization = "Bearer $token" }

# 内置版式清单（恰好 4 条）
Invoke-RestMethod 'http://localhost:8080/workflow/print/builtinTemplates' -Headers $h | ConvertTo-Json -Depth 4

# 某版式的栏目（未知 key 回退 contract）
Invoke-RestMethod 'http://localhost:8080/workflow/print/defaultFieldMap/fund' -Headers $h | ConvertTo-Json -Depth 6

# 保存某个单据模板的内置版式选择
$body = '{"templateId":"<单据模板ID>","builtinKey":"fund"}'
Invoke-RestMethod 'http://localhost:8080/workflow/print/builtinKey' -Method Post -Headers $h `
  -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

> `/workflow/**` 下**未认证请求一律 401**，所以"用未认证请求验证路由"没有区分力 —— 必须带 token。
